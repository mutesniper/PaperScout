# PaperScout v1.1.0

2026-10-28 · 应用标签：`paperscout-v1.1.0`

本版本新增可选 **LLM-as-a-Judge**，在既有检索指标与引用来源校验之外，对单篇论文问答的正确性、完整性、证据支持度进行模型评分。裁判独立于日常功能，默认关闭。

## 新增与改进

- 独立 `--live --judge` 评测入口，支持与 `--semantic` 组合；裁判使用独立的 `JUDGE_*` 配置。
- 每项 0–2 分及评分理由，单独记录裁判耗时、Token、运行错误、有效计数和提示词哈希，保留人工审核项。
- 增加模拟服务测试，覆盖配置检查、拒答、格式错误、截断、超时与费用分离。
- 完成三篇真实论文 12 道题的回答与裁判评分，另设三个错误对照；详细记录权限错误、重评过程与评分局限。
- README 补充技术栈徽章、模型分工、配置与使用示例、FAQ、文档导航和未来规划；项目采用 MIT 许可证。

## 本轮真实评测

回答模型 `deepseek-v4.1-flash`，Embedding `qwen3.7-text-embedding-flash`，裁判 `qwen3.8-max-0902`。名称按配置服务的模型标识记录。

| 指标 | 结果 |
| --- | --- |
| 问答与裁判有效运行 | 12/12 |
| 标注证据 Hit@6 | 9/9 |
| 正确性 / 完整性 | 均分各 2.00/2，12 题 |
| 证据支持度 | 均分 2.00/2，9 道有引用回答；3 道拒答不适用 |
| 预设错误对照 | 错数字、漏答、不支持的引用均触发相应维度扣分 |

这组固定开发样本未经独立人工盲审，模型分数不等于人工正确率或完整 Agent 成功率。错误对照也暴露出必要要点解释的局部不一致；对照不计入正式成绩。[逐题记录、用量与限制](https://github.com/mutesniper/PaperScout/blob/paperscout-v1.1.0/docs/evaluation/LLM_JUDGE_RESULTS.md)。

## 获取与使用

下载本 Release 自动生成的 **Source code (zip)**，或获取固定版本：

```bash
git clone --branch paperscout-v1.1.0 https://github.com/mutesniper/PaperScout.git
cd PaperScout
```

本地开发及 Docker 启动见[本版本 README](https://github.com/mutesniper/PaperScout/blob/paperscout-v1.1.0/README.md)。已有用户更新源码后重启后端与前端；Docker 使用 `docker compose up --build -d` 重建应用，保留现有数据卷，无新增数据库迁移。

使用裁判评测时，在根目录 `.env` 配置 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 及 `JUDGE_BASE_URL`、`JUDGE_API_KEY`、`JUDGE_MODEL`，在已准备好项目 Python 环境的根目录运行：

```powershell
.\.venv\Scripts\python backend/evaluation/run.py --live --judge
```

默认使用虚构材料回归集，真实论文样本的准备、语义检索与评分规则见[评测指南](https://github.com/mutesniper/PaperScout/blob/paperscout-v1.1.0/docs/evaluation/EVALUATION.md)。真实模型调用会消耗服务额度；配置裁判不会给日常问答增加调用。
