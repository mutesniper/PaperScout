# 小模型微调与接入计划

[返回首页](../README.md) · [项目计划](PLAN.md)

状态：待实施。2026-10-27 制定；本文不表示训练、数据准备或模型接入已经完成。

## 目标与职责

在已有 PaperScout 上补齐「数据制作 → SFT/QLoRA → 评测 → 本地推理 → 应用接入」工程闭环。无需提出新算法，不以训练损失下降代替实际效果验证。

首期让小模型将用户的非专业描述转成项目已有的检索计划：1～3 个简短英文检索词、可选起止年份。优先输出一组核心检索词；确有不同检索角度才拆成多组。检索词表达概念，不生成未经检索的论文标题、引用或 PDF 链接。

| 工作 | 首期使用模型 |
| --- | --- |
| 中文想法 → 检索计划 | 原始小模型 / 微调小模型 / 云端模型，显式选择 |
| PDF 摘要、证据问答、论文对比 | 保留现有云端模型 |
| 单/多 Agent 工具决策 | 首期保持云端，第二阶段再训练小模型 |
| Embedding | 保留独立配置，不属于本次生成模型微调 |

注意：当前独立 `/plan` 和 Agent 的 `search` 决策是两条入口。只微调并接入检索计划，不代表 Agent 已改用小模型。真正展示小模型 Agent 控制能力需完成下文第二阶段。

## 硬件与技术栈

已知用户电脑：RTX 4060 Laptop 8GB 显存、约 16GB 内存。首选 Qwen/Qwen3-1.7B 的非思考模式；若显存或训练速度不合适，再评估同系列 0.6B。型号是候选，不承诺给定配置一定可训练。

- 训练：Python、PyTorch/CUDA、Transformers、Datasets、PEFT、TRL、bitsandbytes。
- 方法：SFT（监督微调）+ QLoRA（4-bit 加载基础权重，仅训练 LoRA 参数）。不从零预训练。
- 环境：优先独立 WSL2/Linux GPU 环境；先检查驱动、CUDA 和量化依赖兼容性，再锁定通过验证的版本。训练依赖不加入现有后端 requirements。
- 推理：先用 Transformers + PEFT 加载基础模型与 adapter 验证；再以独立本地 HTTP 服务接入 FastAPI。首期无需转换 GGUF 或合并权重。
- 数据与评测：JSONL、Pydantic 校验、固定测试集、JSON/Markdown 报告。

技术依据：[Qwen3-1.7B 模型卡](https://huggingface.co/Qwen/Qwen3-1.7B)、[PEFT 量化训练](https://huggingface.co/docs/peft/developer_guides/quantization)、[TRL SFTTrainer](https://huggingface.co/docs/trl/sft_trainer)。执行时核对模型 chat template、非思考模式和 assistant loss mask，不手写不兼容模板。

## 第一阶段：检索规划模型

### 1. 固定输入输出与基线

沿用现有 Plan：`queries`、`year_from`、`year_to`；相对年份要在输入中明确当前日期，不能靠模型记忆年份。无年份要求用 null。排除年份矛盾等需要改接口支持澄清的输入，另列能力边界。

例如输入：「当前日期 2026-10-27。想找 2023 到 2025 年，让小模型自动调用工具的论文。」

```json
{"queries":["small language models tool calling"],"year_from":2023,"year_to":2025}
```

先固定 100～150 条测试目标，覆盖中文口语、英文、明确年份、相对年份、长描述、不同学科和工具调用方向。相似目标和改写按组分割，锁定测试集后再制作训练集。模型比较使用相同提示、上下文和解码策略；云端模型只是参考，不充当唯一答案。

交付：任务规格、评测样本、基础小模型与云端基线报告。先测原始模型，效果已足够时仍可训练学习流程，但必须诚实报告提升幅度。

### 2. 制作训练数据

先做 100～200 条人工核验的小样本，跑通训练后再扩展到约 1000～2000 条；数量是起点而非质量保证。

- 人工编写目标与计划，可用云端模型辅助扩写，再人工抽检与自动校验；调用前确认使用范围和预算。
- 保存来源、主题组、数据版本、生成方式及修订记录。真实用户历史脱敏后才能使用。
- 覆盖非专业描述到术语映射、简短关键词、年份约束以及过长查询的修正。不要只用 TinyAgent 等少数论文名做训练。
- 使用对话格式 JSONL：system 定义任务，user 包含日期和目标，assistant 只给符合 schema 的 JSON；不训练思维链。
- 全量检查 JSON/schema、年份范围、重复、空词、长度；人工检查概念是否准确、是否擅自补充限制。验证集与测试集不得混入训练。
- 测试按语义约束判断允许不同合理检索词，不用参考 JSON 字符串完全一致率衡量任务正确性。

交付：数据卡、train/validation/test 划分、校验脚本、审核样本。测试目标一旦用于调参，应移入验证集并重新建立未见测试集。

### 3. QLoRA 试训

以下为待显存验证的起始配置，而非保证值：

| 参数 | 起点 |
| --- | --- |
| 权重量化 | NF4 4-bit，double quantization |
| 序列长度 | 1024 tokens，必要时降到 512 |
| 每设备 batch / 梯度累积 | 1 / 8 |
| LoRA rank / alpha / dropout | 8 / 16 / 0.05 |
| 学习率 / epoch | 1e-4 / 1～3，依验证集选择 |
| 显存控制 | 梯度检查点、关闭训练 KV cache |
| 计算精度 | 先检测 BF16 支持，否则验证 FP16 |
| loss | 只计算 assistant 输出；检查模板与 mask 实际生效 |

先用 20～50 步检查显存、loss、标签 mask、保存与恢复；记录峰值显存和吞吐，再估算完整训练时间。显存不足先缩短序列、关闭其他 GPU 程序，再考虑更小模型。不要截断 assistant 的 JSON 标签来凑长度。

只保存 adapter、tokenizer 配置、基础模型 revision、数据哈希、训练参数和日志。权重与大数据文件放忽略目录，仓库保留配置、小样例及复现说明。第一版不安排 DPO 或 Agentic RL。

### 4. 评测与错误分析

比较原始小模型、微调小模型、云端模型三组，保留失败，不只展示好案例。

| 指标 | 如何验证 |
| --- | --- |
| JSON/schema 合法率 | 直接解析生成结果，单独统计格式修复后的成绩 |
| 年份条件准确率 | 明确和相对日期测试，含无年份要求 |
| 意图保留与术语质量 | 依据人工标注约束检查，不按单一关键词答案评分 |
| 检索有效性 | 固定来源响应做回归；另用少量真实搜索做辅助验证，区分来源限流与模型质量 |
| 延迟与资源 | 相同输入和输出上限、预热后测多条，报告中位数/P95、峰值显存 |
| 调用成本 | 本地模型不计云端推理费，但有硬件耗时；云端缺少 usage 时记未知 |

建议首期接入门槛：固定测试集 schema 合法率至少 95%，年份准确率至少 95%，人工审核无明显意图丢失；这些是目标，不是实测结果。若微调没有提升，先查数据分布、训练模板、标签与超参数，不承诺一定优于基础模型。

### 5. 应用接入与切换

当前所有生成任务共用 LLM 配置，不能直接整体替换为小模型，否则摘要和对比也会一起切换。

计划新增独立的检索规划 provider：cloud / local，默认 cloud；local 指向独立推理服务，服务可切换基础权重或基础权重 + adapter，报告记录实际模型版本。只有检索计划调用此 provider，其余生成任务仍走现有配置。

- 沿用 `/plan` 输出结构与 Pydantic 验证；本地失败明确提示，不静默调用付费云端。
- 前端用一个简洁选项选择检索计划模型，说明放现有使用指引。避免把模型配置表搬进业务页面。
- 首期只允许可信本地推理端点；设置超时、并发上限和取消。Docker 访问宿主服务的地址单独说明。
- 验收原有云端模式不受影响，本地模型真实输出能驱动搜索，重启恢复配置一致。

## 第二阶段：小模型 Agent 决策（第一阶段验收后）

训练「目标 + 当前可用 PDF/候选 + 最近工具结果 + 剩余额度 → 下一步合法动作」。先接入单 Agent，再考虑多角色，不同时替换所有模型职责。

样本包含 search、download_pdf、answer、compare、finish，以及已有 PDF 不应下载、下载超时/来源失败后的合法恢复、证据不足应结束等场景。用人工纠正的正确动作训练；错误动作作为输入情境，不把错误调用当作 assistant 标签。先设计紧凑上下文，再定长度，不能把当前长事件记录直接塞进 1024-token 样本。

评测采用工具模拟环境，验证工具选择、参数合法性、任务内 ID、重复调用、预算遵守、任务完成率；再小批量跑真实搜索下载，来源故障单独归因。只有完成该阶段才能宣称「微调小模型控制 Agent 工具调用」。摘要、证据回答仍可由云端模型负责，形成明确的混合模式。

## 推进顺序与交付

1. 任务与测试集定稿，测原始小模型基线。
2. 核验 GPU 环境，跑 100～200 条数据的小规模训练。
3. 数据审核后扩充，训练并保存可复现 adapter。
4. 同测试集评测，出具结果与失败分析。
5. 接入显式模型选择，验证云端与本地模式。
6. 再启动 Agent 动作决策数据与训练。

首期按兼职学习节奏预留约 1～2 周；依赖安装和数据审核可能更久，不预先承诺训练耗时或性能收益。当前下一步是第 1 项，不需要马上下载全部权重或启动付费训练。

| 优先级 / 时点 | 待办 | 来源 | 验收与边界 |
| --- | --- | --- | --- |

| P1：交付补齐 | 收藏论文与取消收藏，独立收藏列表 | 原始交付计划 | SQLite 持久化、去重、重启可恢复；与检索历史/论文库分开。可在微调试训之后实施，不是训练前置 |

| P1：训练 Agent 决策时 | 来源规则的查询前适配与异常回退 | 后续新增来源适配计划 | 档案读取、按来源构造查询、保留用户约束，测试年份/短语/关键词；不让小模型凭空生成网站规则 |
| P2：主线完成后 | 摘要任务总预算、已验证中间/最终结果缓存、短中长文对照 | 后续摘要降耗计划 | 当前已有单次输出限制和降耗；尚缺整次预算/可靠缓存及多长度对照。保持全文覆盖，不自动加大输出额度重试 |
| P2：按需 | 多轮问答、OCR、重排序 | 后续或可选扩展 | 分别独立评估，不作为本次微调交付条件 |

安全与可信性回归继续沿用现有工具 ID 校验和下载检查；Agent 决策评测补充论文中的提示注入、无效参数、越权 ID 等用例，确认工具返回与文献文本不能覆盖系统约束。这是验证工作，不宣称防护完全可靠。

远程 MCP、多用户鉴权、专家并行、Agentic RL、页面全文阅读均不并入本轮必做项；前三类属于新范围，RL 原计划已排除，全文阅读已被用户取消。

**合并后的下一步仍是：固定检索规划任务与测试集，同时整理最小来源规则，然后运行原始小模型基线。** 不要求先补完收藏、OCR 或所有产品改进才能训练。
