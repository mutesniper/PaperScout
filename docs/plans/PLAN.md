# PaperScout 项目计划

## 目标

展示 AI 应用工程能力：从研究想法发现论文，明确获取状态，逐步扩展到有证据的阅读和问答。先完成云端大模型版本，小模型留在后续阶段。

## 第一版：云端大模型

1. **检索闭环（已实现）**：Vue + FastAPI；两个真实来源；可编辑检索计划；规范化与保守去重；全文状态依据；SQLite 缓存和历史；超时、取消、限流、部分失败；独立模型接口。
2. **全文摘要（已实现）**：公开 PDF 获取与上传；提取完整文本；生成一份涵盖目标、方法、结果和局限的全文摘要；区分来源摘要概括；保留可核对原句依据与本地历史。
   不提供页面内全文阅读、章节导航或逐页摘要。长文内部提取信息后综合，只输出一份摘要；失败不保存部分结果冒充成功。OCR 与复杂版式精确还原不在本阶段，真实模型须配置后验收。
3. **RAG 问答与对比（已实现）**：独立 Embedding 接口；FAISS + 关键词融合检索；单篇论文隔离及默认全文检索；原文证据编号核验；依据不足时明确说明；历史恢复与取消。未配置向量模型时使用明确标注的关键词模式。支持 2～5 篇 PDF 按目标、方法、实验设置、结果和局限生成对比表，各单元格分别校验证据归属。多轮上下文留待后续。
4. **单 Agent 编排（已实现，本地自动化验收通过）**：LangGraph 决策与工具执行循环；模型按目标选择查询、候选、公开 PDF 获取、证据问答与对比；每次一组核心词，优先 arXiv，成功但空结果时最多简化虚词重试一次；未找到标题匹配的公开全文且公开全文候选不足 5 篇，或来源失败时补充 Semantic Scholar；允许两次检索以改写查询；SQLite 任务记录、后台运行、进度恢复、取消、超时与调用/输入量上限。真实搜索、下载与问答链路已有单/多模式验收记录；更广泛稳定性验证仍待完成。服务重启后标记中断、保留已有结果，不自动续跑收费操作；本地 MCP 与可选多 Agent 已实现，见下文；默认保留单 Agent。
5. **交付（进行中）**：已加入离线固定样本检索评测、可选真实模型问答评测和 JSON/Markdown 评测报告，见 `docs/evaluation/EVALUATION.md`。已完成三篇真实论文、12 题的初步云端验证，结果见 `docs/evaluation/EVALUATION_RESULTS.md`；独立人工复核和更广泛质量验收仍待完成。摘要、问答和对比的 Markdown 导出、Docker Compose 启动及演示说明已实现，见 `docs/guides/DEMO.md`；收藏仍待实现。本地 MCP 与可选多 Agent 扩展已完成，后续继续完善真实模型验收与效果对照。

每阶段运行验收后再继续；不把后续功能标记为已实现。生成模型与 Embedding 模型分别配置。

### 检索排序增量（2026-10-22）

候选获取规则：支持相关性排序的来源优先使用相关性顺序，否则沿用来源默认顺序；多行关键词分别查询，每组每来源最多获取 100 篇，同来源交替合并去重后最多保留 100 篇候选。多来源相关性模式采用 RRF；用户选择时间或引用量时仍执行相应本地字段排序。

已实现：候选数和返回条数分离；单来源保持顺序，多来源 RRF；本地日期与引用量排序；保留来源排名、缺失值提示和历史兼容。排序范围仅为本次候选，未实现全库高引召回或下载量统计。

## 后续改进：来源规则与检索适配（待实现）

提前获取各论文网站的检索规则与查询偏好，保存在本地；每次检索前先读取相应来源的信息，再构造适合该网站的查询。

- **本地来源档案**：记录支持的检索字段、关键词与短语语法、AND/OR 规则、语言支持、排序能力及默认顺序、分页与结果数量上限、认证要求和调用频率限制。凭据仍单独保存在环境变量中。
- **规则依据与维护**：优先依据官方 API 文档，记录文档链接、核验日期和规则版本；通过测试观察到的查询偏好单独标注，不作为网站保证。定期或接口异常时复核更新。
- **查询前适配**：读取来源档案，将统一检索意图转换为各来源支持的查询表达式和参数，保留用户明确要求的条件；避免对所有网站机械套用同一套关键词拼接规则。
- **执行与回退**：按来源支持的相关性排序和数量限制获取候选；档案缺失、过期或能力不支持时，采用已验证的基础查询并提示限制，不凭空构造参数。
- **验收方式**：用固定案例验证短语、多个关键词、年份和排序在不同来源上的表现，并记录生成的查询及所用规则版本，方便定位漏检原因。

## 后续改进：全文摘要 Token 消耗与成本控制（部分完成）

用户反馈一次总结消耗约 120k tokens，需要排查并降低成本。该数值尚未按请求核验，需区分单次摘要任务、截断重试及诊断复测的累计用量，不能把输出上限当作实际消耗。

- **用量统计**：记录每次模型请求及整次摘要任务的输入、输出、推理 Token（服务提供时）、重试次数和耗时；以服务返回的 usage 为依据，避免重复累计推理 Token 等子项。缺少数据时标记未知，不伪造精确用量。
- **减少调用与重复输入**：结合模型上下文容量和预估 Token 数选择处理方式，普通长度论文优先一次调用；仅在必要时分段综合。精简提示词和中间结果，在保持内容覆盖与摘要质量的前提下降低消耗。
- **推理与输出控制**：模型服务支持时提供关闭深度思考或降低推理强度的配置；按任务设置合理输出额度，避免为短摘要持续扩大输出预算。
- **整次任务预算**：设置总 Token 预算与最大调用次数，将所有分段、综合和重试计入预算；调用前检查剩余额度，预算不足时停止并明确提示。预估用量与实际计费用量分开展示。
- **重试与结果复用**：收紧自动重试策略，不因输出截断而无条件扩大额度；按文件内容、模型和提示词版本缓存已验证的中间结果及最终摘要，避免失败后整篇重跑或重复生成。
- **验收方式**：使用同一组短、中、长论文比较优化前后的实际 Token 用量、调用次数、耗时及摘要质量；覆盖预算不足、重试失败和缓存命中场景，确认不会以漏读内容或降低证据可靠性换取低消耗。

2026-10-24 已完成后端降耗，不新增用量页面或预算控件：普通长度论文改为完整单次调用（48000 字符以内）；对已识别且支持的服务关闭摘要任务深度思考；输出额度默认 4096，取消截断自动重试；后台仅记录服务实际 usage，压缩请求序列化空白。证据校验与全文覆盖保持。

同一份 2505.08588v1.pdf 真实复测：1 次调用，输入 9234、输出 384、总计 9618 tokens，生成 580 字摘要和 8 条校验通过的证据。服务未返回推理 Token 子项，不将其写作零。旧 120k 用量无逐请求记录，不作同条件节省比例结论。总预算、缓存复用、多长度样本质量对比等仍待实现；当前不新增用户功能或页面。

### MCP 工具接口（本地版已实现）

已提供搜索、公开 PDF 导入、论文库列表、元数据与已有摘要读取、生成摘要、RAG 问答及论文对比工具。原文检索包含在问答与对比中，暂不单独开放证据检索工具。通过调用现有 HTTP 接口复用业务逻辑。

先提供本地接入，后续按需扩展远程服务；定义结构化输入输出和错误信息，区分只读检索与会调用付费模型、下载文件或写入记录的工具。限制可访问的论文和文件范围，不暴露密钥或任意文件读取能力。验收覆盖客户端发现工具、实际调用、错误返回、取消及证据来源保持。

### 多 Agent 编排（已实现，已有真实链路验收）

基于 LangGraph 实现三角色串行协作，使用同一个已配置模型、不同角色提示词和工具权限。协调者按需委派，每次专家选择一个工具或报告阻碍，执行后回到协调者，并非每次都调用全部角色：

- **协调 Agent**：理解用户目标、拆分任务、选择角色，控制执行轮数与总调用预算。
- **检索 Agent**：改写检索词，复用当前来源适配搜索、筛选候选并获取公开 PDF；仅允许 search/download_pdf/report。按当前候选和预算过滤可选操作，已有 PDF 直接交给分析角色。
- **分析 Agent**：复用 RAG 问答和多篇对比工具，输出带原文依据的结果；仅允许 answer/compare/report，不自行生成未经校验的研究结论。

共享候选、PDF ID、尝试记录、下载失败原因及简短已校验结果，不在角色之间反复传递全文。共用 12 次生成、80 次 Embedding、300000 输入字符和 600 秒任务上限；单 Agent 最多 10 次决策，多 Agent 最多 18 次角色决策，任一预算先耗尽即停止。工具上限不变：搜索 2、下载 5、对比 1、问答 2；连续两次无操作报告或连续两次重复/超额操作会停止。支持取消、任务持久化与重启标记中断，不自动恢复收费执行。

网页支持模式选择并默认单 Agent；历史保留 mode 和角色事件，旧记录按单 Agent 展示。内部直接复用工具，不经过 MCP。未实现并行专家、独立模型配置或自动单/多模式切换；阅读/综合角色进一步拆分留待质量与成本评估后决定。

### 分工与验收

MCP 负责工具接入协议，多 Agent 编排负责角色协作，两者可以独立使用。内部角色可以直接调用共享业务工具，不强制所有内部调用经过 MCP。

用固定任务比较单 Agent 与多 Agent 的结果质量、证据正确性、任务完成率、调用次数、Token 用量及耗时；保留简单任务的直接执行路径，只有协作带来可验证收益时才扩大使用范围。真实模型与 MCP 客户端联调完成后再标记验收通过。
