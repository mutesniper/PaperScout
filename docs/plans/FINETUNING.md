状态：**当前采用第三组第 3 轮适配器，单 Agent 可切换本地实验路由，默认云端模式保留。** 第四组低学习率续训已完成，开发验证虽提高，但测试候选出现新的网络权限错误，模拟任务完成从19/20降到18/20，按预登记规则不采用。原120条测试候选已首次评分。详见[第四组报告](../evaluation/router/CONSERVATIVE_RUN.md)、[当前模型报告](../evaluation/router/PROGRESSION_RUN.md)及[本地模式启动](../guides/LOCAL_ROUTER.md)。

## 1. 目标与范围

训练「用户目标 + 当前任务状态 → 下一步操作类型」，展示数据制作、SFT/QLoRA、对照评测与 Agent 接入能力。首期只选择有限类别，不训练自由文本理由、工具参数或思维链，不安排预训练或 Agentic RL。

| 职责 | 本期安排 |
| --- | --- |
| 下一步操作类型 | 原始小模型 / 微调小模型 / 云端，同契约比较 |
| 顶部检索计划、英文关键词、年份 | 保持云端，不训练 |
| 论文ID、检索计划、问题、对比维度等参数 | 现有云端参数生成及后端校验，不计为小模型路由成绩 |
| 摘要、证据回答、对比结论 | 保持现有云端模型 |
| Embedding、MCP、多Agent | 保持原状，本期先接入单Agent |

路由任务较容易界定，但不保证微调有效；选对工具不等于参数正确或整个任务完成。

## 2. 路由标签与现有代码

依据：[Agent循环](../../backend/app/agent/core.py)、[工具契约](../../backend/app/tools/schemas.py)、[执行器](../../backend/app/tools/executor.py)。现有动作是search、download_pdf、answer、compare、finish；没有clarify工具或独立摘要动作。

| 标签 | 典型状态 | 后续执行 |
| --- | --- | --- |
| search | 需找论文，候选不足且搜索额度可用 | 云端生成SearchAction.plan |
| download_pdf | 有合适候选和公开链接，但缺少分析所需PDF | 云端选择候选paper_id，后端检查归属和重复 |
| answer | 已有PDF，需要单篇证据回答 | 云端生成reading_id和question |
| compare | 至少两篇相关PDF，需要比较 | 云端生成ComparisonRequest，后端校验ID与数量 |
| finish | 目标完成或存在明确不可继续的阻碍 | 根据实际进度结束，失败不能标为完成 |
| clarify | 指代/目标不明确，无法合理补全 | 新控制分支，不直接传现有工具执行器 |

同样拥有两篇PDF，单篇提问仍应选answer，不能只看数量就选compare。通用闲聊不加入标签，不照搬no_tool作为长回答入口。

clarify第一阶段只离线评测。接入时最小实现为提示补充信息并结束本次任务，补充后新建任务；可恢复的人机中断不属于本期。

## 3. 输入输出契约

后端构造紧凑状态：目标、允许操作、候选简要状态、可读PDF、已完成结果、最近失败、剩余额度。保留paper_id与reading_id区别，不传整篇PDF、完整聊天记录或密钥。

输入示例：

```json
{
  "goal": "比较已选两篇论文的方法",
  "available_pdfs": [{"reading_id":"r1","title":"论文A"},{"reading_id":"r2","title":"论文B"}],
  "allowed_routes": ["search","answer","compare","finish","clarify"],
  "progress": {"has_comparison":false},
  "recent_outcomes": [],
  "remaining": {"search":2,"download_pdf":5,"answer":2,"compare":1}
}
```

唯一训练输出：

```json
{"route":"compare"}
```

新增独立RouteDecision/Pydantic枚举契约，拒绝额外字段；不能直接替换现有Action。allowed_routes依据客观资源和额度构造，不包含正确答案提示；保留多个可行动作来考核决策。状态压缩必须保留关键失败、进度与预算，超长不能静默截掉约束或标签。

## 4. 数据与隔离

先制作并审核60条规格样例，每类约10条。原数量目标400/80/120不再靠扩写凑齐：v2实际为**84条训练、36条验证、120条测试候选**，每行是不同目标—状态；测试候选每类20条。正式训练前根据基座诊断补充训练案例，测试候选仍未独立审核封存，数量不代表质量。

按完整任务/场景族划分：同一目标的改写、一次轨迹的各步骤和换ID变体不得跨集合。先确定划分再扩写，不以模板换词后的随机划分宣称未见任务泛化。

覆盖以下对照：

- 同一需求在没有PDF、已有PDF、已有结果时的不同操作。
- 相同两篇PDF下，单篇问答、多篇对比、只找链接的不同目标。
- 已下载不得重复下载；下载失败后换候选、搜索或停止，按具体状态标注。
- 无候选、无公开链接、来源限流、信息不足、预算耗尽及取消。
- 任务完成必须结束，未完成不能过早结束；可继续时不应习惯性澄清。
- 中文、英文、口语；论文标题或工具结果中的指令不能覆盖任务约束。

每条保存场景组、输入、主标签、允许的等价下一步、标注依据、来源和审核状态。多种顺序合理时先明确优先规则，或使用允许集合评分；主标签用于SFT，等价集合命中与精确匹配分开报告。

60条规格样例逐条审核；正式数据全量校验schema、前置条件、重复，按类别审核标签。Codex辅助审核和用户/独立人员审核分别标注，不把自审称为独立人工金标准。真实历史需脱敏并明确用途；云端扩写不是前置条件，如需使用，另行确定范围和调用预算。

## 5. 基线、环境与训练

先比较简单规则基线、原始小模型和云端模型。规则基线用于判断是否需要学习；云端不是唯一答案或所有标签的裁判。基础与微调模型使用同一revision、提示、状态构造和解码参数。

基座为**Qwen3-4B-Instruct-2507**。模型已由用户下载，独立WSL环境已恢复；本轮最长433 Token，正式训练峰值预留5.36GiB。该结果只适用于当前长度和配置，更长上下文仍需重新测量。需要重新下载时先提供清单及手动方式，沿用用户偏好。

| 项目 | 起点，执行时验证并锁定 |
| --- | --- |
| 环境 | 独立WSL2/Linux虚拟环境，不加入后端requirements |
| 技术 | PyTorch、Transformers、PEFT、TRL、bitsandbytes、Datasets |
| 方法 | SFT + QLoRA，NF4双重量化、BF16计算、冻结基座 |
| LoRA | rank8 / alpha16 / dropout0.05，q/k/v/o投影 |
| 显存 | batch1、梯度累积4、梯度检查点、关闭训练KV cache |
| 长度 | 先统计真实状态，从512评估；确需1024时重新试跑，不能删除关键状态凑长度 |
| 学习率/轮数 | 2e-5起点，1～3轮，按验证集选checkpoint；正式运行前冻结上限 |
| 监督/推理 | 只对assistant路由JSON计算loss；原生chat template；确定性生成、短输出上限 |

先10～20次更新检查真实长短状态、标签mask、非零梯度、显存、保存与独立重载。正式训练从原始基座开始，不续接试跑权重。保存模型revision、数据/提示哈希、依赖锁、配置、种子、adapter与日志。

首批最多2个预先登记的正式配置，只依据训练/验证集改进；测试集仅对最终候选解封一次。看过测试错误后不自动重跑，用于下轮改进的题必须转为开发集。若基座已足够好，仍可完成学习实验，但如实报告微调无额外收益，不强行部署。

2026-10-28用户授权新一轮数据改进、训练与评测：追加一组固定3轮的配置，228条训练样例；新增36条训练前冻结的诊断集，不参与选模。原120条测试候选继续封存；不自动追加第四组。详见[第三组预登记与结果](../evaluation/router/PROGRESSION_RUN.md)。

## 6. 离线验收

严格解析原始输出；围栏去除或字段修复后的成绩单列。所有模型使用同一测试文件和分母，保留逐条输出、错误、类别数量与混淆矩阵。

| 指标 | 预定目标，非实测结论 |
| --- | --- |
| 原始schema合法率 | ≥99% |
| 合理路由命中 / Macro-F1 | 允许集合命中≥90%；固定主标签Macro-F1≥0.90 |
| 类别召回 | 每类≥80%；同时报告精确率和澄清/结束混淆 |
| 权限与预算边界 | 固定边界集无越权选择，后端全部拦截非法动作 |
| 过早结束 | 应继续的样例中错误finish≤2%，遗漏步骤单列 |
| 微调收益 | 同基座命中率至少增加5个百分点，无关键类别明显退化 |
| 资源/延迟 | 预热后P50/P95、峰值显存、输入输出Token和状态长度 |

区分“满足使用条件”和“微调有收益”：基座已达标但adapter无提升，不能称作微调成功。小样本差异不等于统计显著；仍需独立语义复核及完整任务验证。工具参数准确率不计为路由成绩，但接入验收必须检查参数可执行性。

## 7. 闭环验证与接入

离线通过后，先做约24个固定模拟任务，含正常多步、失败、预算不足、已有PDF和澄清；与训练场景分组隔离。用相同工具响应、参数生成策略、提示和预算对照原始/微调/云端路由。若比较当前云端一体决策，单列架构差异。

```text
任务状态 → 小模型选择route → 校验允许操作
        → 云端在选定工具schema内生成参数 → 现有Action校验
        → ToolExecutor执行 → 更新状态 → 再次路由
```

finish按完成/阻碍状态生成简短说明，clarify走新控制分支。云端参数构造可复用agent_decide，但仅允许已选工具的schema，并核验tool一致；不得暗中重选来掩盖路由错误。

统计任务完成率、无效/重复调用、过早结束、参数失败、总耗时、总云端请求和实际usage。路由正确但参数失败计为流程失败。**本地路由不保证省云端费用**：参数和内容生成仍调用云端，次数可能增加。

模拟闭环目标：完成率至少90%，不低于同参数生成条件的云端路由；权限、预算、重复操作检查全部通过。然后选5～10个真实任务辅助验证，网络故障单独归因；收费验证在预算与发送内容明确后执行。

2026-10-28已完成隔离的受控任务对比：20个研究任务模拟完成率基座70%、微调85%，4个控制场景正确率75%→100%；仍有顺序/选择约束违规。该轮只调用本地路由模型，工具参数用理想固定绑定器、工具内容用模拟回执，未比较云端路由、真实参数生成或回答质量，不能据此通过本节接入验收。详见[分层任务评测](../evaluation/router/LAYERED_EVAL.md)。

最后增加独立router provider（cloud/base/finetuned），默认云端，只影响单Agent决策。顶部/plan、摘要/RAG/对比配置不变，多Agent保留原路径。本地服务限定并发、超时并记录版本；失败不静默回退。统计涵盖本地路由和云端参数请求，不绕过现有次数、字符、步骤与超时上限。
