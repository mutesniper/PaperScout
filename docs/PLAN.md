# PaperScout 项目计划

## 目标

核心定位：用户知道想实现的目标但不了解专业术语。系统分析非专业描述，提出知识集与候选实现路线，让用户点击知识点查找相关论文，再逐步用论文证据完善路线。展示 AI 应用工程能力，先完成云端大模型版本，小模型留在后续阶段。

## 第一版：云端大模型

1. **检索闭环（本次）**：Vue + FastAPI；两个真实来源；可编辑检索计划；规范化与保守去重；全文状态依据；SQLite 缓存和历史；超时、取消、限流、部分失败；独立模型接口。
2. **阅读闭环**：合法公开 PDF 获取与上传；解析章节和页码；按章节总结；区分摘要总结与全文总结；可追溯证据。
3. **RAG 问答**：独立 Embedding 接口；FAISS；来源及章节过滤；引用核验；没有证据时说明不足。
4. **Agent 编排**：LangGraph 主 Agent；查询改写、全文查找、补充阅读；状态持久化；有界工具调用与成本预算；将文献内容视为不可信资料。
5. **交付**：收藏、Markdown 导出、固定样本评测、Docker、演示和复现说明。

每阶段运行验收后再继续；不把后续功能标记为已实现。生成模型与 Embedding 模型分别配置。

### 检索排序增量（2026-10-22）

候选获取规则：支持相关性排序的来源优先使用相关性顺序，否则沿用来源默认顺序；多行关键词合并为一次查询，每来源固定最多取前 100 篇，不按关键词行数倍增。多来源相关性模式采用 RRF；用户选择时间或引用量时仍执行相应本地字段排序。

已实现：候选数和返回条数分离；单来源保持顺序，多来源 RRF；本地日期与引用量排序；保留来源排名、缺失值提示和历史兼容。排序范围仅为本次候选，未实现全库高引召回或下载量统计。

### 目标分析与知识导航（2026-10-23）

已实现：非专业目标分析、假设和必要的澄清、核心/可选知识卡片、实施步骤及替代路线；卡片支持编辑、删除、补充；点击后携带目标背景执行检索，检索历史保留目标与知识点。初步建议明确标记为尚未经论文证据核验。

后续：持久化完整分析与编辑版本；阅读论文后解释其对目标的具体帮助，并基于证据修正路线。当前完整分析只保存在页面内存中。

## 后续改进：来源规则与检索适配（待实现）

提前获取各论文网站的检索规则与查询偏好，保存在本地；每次检索前先读取相应来源的信息，再构造适合该网站的查询。

- **本地来源档案**：记录支持的检索字段、关键词与短语语法、AND/OR 规则、语言支持、排序能力及默认顺序、分页与结果数量上限、认证要求和调用频率限制。凭据仍单独保存在环境变量中。
- **规则依据与维护**：优先依据官方 API 文档，记录文档链接、核验日期和规则版本；通过测试观察到的查询偏好单独标注，不作为网站保证。定期或接口异常时复核更新。
- **查询前适配**：读取来源档案，将统一检索意图转换为各来源支持的查询表达式和参数，保留用户明确要求的条件；避免对所有网站机械套用同一套关键词拼接规则。
- **执行与回退**：按来源支持的相关性排序和数量限制获取候选；档案缺失、过期或能力不支持时，采用已验证的基础查询并提示限制，不凭空构造参数。
- **验收方式**：用固定案例验证短语、多个关键词、年份和排序在不同来源上的表现，并记录生成的查询及所用规则版本，方便定位漏检原因。

## 后续：小模型

1. 选择结构化检索规划作为首个任务，制作并人工检查样本。
2. 划分独立测试集，避免相似任务泄漏。
3. 在 8GB 显存条件下优先尝试 1B–1.5B 指令模型 QLoRA。
4. 保存训练参数、数据说明、适配器和训练日志。
5. 增加本地模型适配器，显式选择云端、本地或混合模式；按模型能力限制任务。
6. 同一测试集比较基础小模型、微调小模型与云端模型：格式正确率、条件提取、检索质量、延迟、资源与成本。

不假设微调必然提升性能，不静默回退云端。

## 可选扩展

按实际需求增加 MCP、多 Agent、OCR、混合检索和重排序。Agentic RL 不属于当前交付范围。
