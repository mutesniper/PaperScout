## 三个预设错误对照

正式 12 题都得到满分后，另复制 `aied-size` 的原回答构造三种错误，仅改待评回答，保持问题、参考答案、检索片段和裁判提示词不变。调用前固定判据：被针对的维度分数应低于 2；不根据结果调整判据，不把这些样本混入正式成绩。

| 人为改动 | 预设检查维度 | 正确性 / 完整性 / 支持度 | 是否识别 |
| --- | --- | --- | --- |
| 将 Phi-2 参数从 2.7B 改为 70B，保留原引用 | 正确性 < 2 | 1 / 1 / 0 | 是，指出数字与原文矛盾 |
| 删除 Phi-2 参数量，仅保留 SLM 定义阈值 | 完整性 < 2 | 2 / 1 / 2 | 是，指出遗漏第二个子问题 |
| 两条结论都改引 c14；该片段只支持 Phi-2 参数量，不支持 SLM 阈值 | 支持度 < 2 | 2 / 2 / 1 | 是，区分结论正确与引用支持 |

本轮三个明显错误均被识别，说明当前调用并非对所有输入都固定打满分；这不是裁判独立准确率评估，不能据 3/3 声称普遍可靠。对照均使用同一道题，没有重复采样或跨裁判一致性验证。

还观察到理由不完全一致：原答案评分称硬件资源要求不属于该问句的必要要点，但错误数字样本的完整性理由又提及遗漏硬件要求。核心错误确实被识别，但这一额外扣分理由提示裁判仍可能随回答内容改变要点判断，需人工复核。

这部分额外调用 3 次、13,369 Token。正式评分与错误对照合计裁判用量为 **56,729 Token**；连同原回答和 Embedding，本次已知成功调用共 **147,020 Token**。13 次历史拒绝请求的用量未知，不纳入已知合计，也不假定免费。

## 裁判权限错误与重评

首轮 12 次裁判调用均返回 HTTP 403。随后仅对第一题复用原回答诊断一次，服务返回 `Access denied by API-Key restrictions.`。回答与裁判使用相同服务及密钥，前者成功、后者被拒绝；可能与裁判模型的权限范围有关，但错误未给出具体限制项。

没有把请求失败记作质量零分或通过，也没有静默替换裁判模型。用户调整 JUDGE 配置后通知继续，模型名称保持 `qwen3.8-max-0902`。重评仅调用裁判，原回答、检索片段、参考答案与标注保持不变；原失败报告保留，新报告注明来源报告及哈希，避免重复计算生成和 Embedding 用量。
