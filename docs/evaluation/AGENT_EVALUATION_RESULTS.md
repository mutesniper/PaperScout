## 单 Agent 失败原因

两次单模式决策都把 `available_pdfs` 中已入库的论文库 ID 传给了 `read.paper_id`，试图先“读取”已有文件。实际上，read 工具负责按搜索候选 ID 下载公开 PDF，而已有论文应直接使用 answer 或 compare。

- 单篇任务：对 TinyAgent 的论文库 ID 调用 read，被候选校验拒绝；随后 finish，错误地推断已有 PDF 不可读，没有调用证据问答。
- 两篇任务：分别对两个论文库 ID 调用 read，均被拒绝；随后 finish，没有调用对比工具。

这是单模式工具选择及错误恢复问题，不是 PDF 内容缺失、Embedding 服务失败或代理错误。边界校验正确地拒绝了错误 ID，但现有提示词和反馈不足以帮助此次模型恢复。

建议后续明确 read/download 的语义、加强两类 ID 的区分，并提示已有 PDF 可直接 answer/compare；修复后用相同目标、资料和缓存条件重测，再讨论模式间效果差异。本轮未修改代码或提示词，也没有隐藏失败样本。

## 证据与内容检查

自动匹配检查：多模式问答含 7 处引用、对比含 5 处引用，**12/12 均能在所属 PDF 对应物理页找到原文**。同一个片段被不同结论引用时分别计数，这不是 12 个独立片段，也不等于语义正确率 100%。

Codex 对输出与引用片段逐项复核（不是独立人工盲审）：

- 问答覆盖 ToolRAG 的 DeBERTa 多标签分类、16 维工具概率、50% 阈值、工具数量/召回率以及减少提示长度的目的。所列关键机制和数字得到第 5–6 页引用支持。
- 对比的 4 个单元格均有引用。TinyAgent 的方法摘要提到工具检索和量化，局限涉及幻觉与合成数据偏见；AgentLoop 的方法涉及在线控制与离线诊断，局限涉及词汇/集合重叠与成组消融。对应引用支持这些陈述，未发现跨论文错引。
- 对比仍偏简略：TinyAgent 的方法单元格没有展开模型微调和规划机制，不应将“4 个单元格有依据”解读为方法与局限已全面覆盖。没有额外模型评分调用。

## 解释边界

本轮只能说明：在这两个固定目标的一次运行中，多模式完成了任务，单模式暴露出已有 PDF 的工具选择问题。单模式较短的耗时来自提前失败，不能作为速度优势。多模式产生更多调用，但失败的单模式不是有效的同质量成本基线。

每种组合仅一个样本，模型输出有随机性；这不是稳定成功率或多 Agent 普遍优于单 Agent 的证明。没有测试真实搜索/下载链路，没有复测全部网页功能。后续先修复单模式问题，再交替运行多次，比较同等完成质量下的耗时与用量。
