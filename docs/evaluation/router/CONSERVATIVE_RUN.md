# 第四组：低学习率续训与不退化验收

2026-10-28。**第四组候选不采用，当前应用继续使用第三组第 3 轮适配器。** 开发验证有所改善，但测试候选新增网络权限边界错误，模拟研究任务完成数从 19/20 降到 18/20，触发事先确定的不退化门槛。

## 改进依据

第三组的主要弱项是缺少目标全文时未搜索、已有可下载候选时重复搜索，以及预算耗尽或选择信息不足时判断错误。继续扩大模型或修改提示词会改变对照条件；这次保持基座、提示词、六类路由和解码方式不变，测试小步续训是否能修正边界而不遗忘已有能力。

- 新增 72 条状态样例、18 个任务族，覆盖缺一篇/候选已找到/全文齐备/已完成等状态，以及检索与分析预算、私人目标、明确指代、执行顺序和不可信文本。
- 完整保留旧训练集 228 条，合计 300 条；旧样例占 76%，用于回放。新增样例不是直接复制评测题或错误轨迹。
- 从当前适配器继续训练，重置优化器，固定 2 轮、150 次更新。NF4/BF16，rank 8，batch 1，累积 4，最大长度 512，不截断。
- 学习率前 8 步预热至 `8e-6`，随后余弦下降至 `2e-6`。不按测试成绩追加轮数、样例或参数配置。
- 仅用原 36 条开发验证集选检查点：原本正确样例退化最少优先，其次动作可用率、准确率、Macro-F1，同分取较早轮。

数据是合成、自审样例，任务族内分支相关，尚未经过独立人工审核。这是数据补充与续训策略的联合实验，不是单因素消融。

## 训练前固定的验收规则

选出一个检查点并在独立进程重载后，用相同环境和贪心解码对照原始基座、当前版和候选版：

| 数据 | 用途 |
| --- | --- |
| 原开发验证 36 条 | 开发选模与回归检查，不能当作盲测 |
| 旧冻结诊断 36 条 | 已观察过，降为本轮回归诊断，不再宣称新测试 |
| 原测试候选 120 条 | 选模后首次模型评分，不回填训练或调参；仍是合成自审候选 |
| 相同 24 个模拟任务 | 20 个研究任务与 4 个控制场景，检查完成率与违规 |

候选必须同时满足以下条件，否则保留当前适配器：

1. 三个单步集合中，当前版答对的每条样例均不退化；准确率、Macro-F1、各类召回、格式和动作可用率不下降，过早结束不增加。
2. 当前版完成的模拟任务不能失败，初始正确路由不能退化，不能新增违规任务；研究/控制任务完成率不下降，过早结束和不必要澄清不增加。
3. 至少修正一个原有错误或失败任务；仅同分不替换。

逐题门槛刻意严格：即使总分更高，也不能掩盖已经正确的案例退化。推理耗时、Token 与显存单独记录；一次运行不用于断言速度提升。模拟任务使用固定工具返回和理想参数绑定，不代表真实论文分析质量。

## 复现命令

在已配置的 WSL 训练环境中，从项目根目录运行。数据文件已经随源码保存，无需重新生成；输出目录必须不存在。

```bash
PY=/home/mutesniper/.venvs/paperscout-router/bin/python
MODEL=outputs/router/models/Qwen3-4B-Instruct-2507
RUN=outputs/router/conservative-20261028-01
$PY -m training.router.conservative_run --model-path "$MODEL" --output-dir "$RUN" --stage prepare
$PY -m training.router.conservative_run --model-path "$MODEL" --output-dir "$RUN" --stage train
$PY -m training.router.conservative_run --model-path "$MODEL" --output-dir "$RUN" --stage reload
$PY -m training.router.conservative_eval --model-path "$MODEL" --training-run "$RUN" --output-dir outputs/router/conservative-eval-20261028-01
```

所有命令只使用本地模型，不安装依赖、不下载基座、不调用云端。评测保存逐条原始输出、完整轨迹及 `decision.json`；脚本本身不修改应用配置。

## 结果

全部 300 条训练输入通过预检，最长 433 Token，无截断；新增训练输入与旧评测输入无完全重复，字面二元组阈值 0.30 未命中新近邻。这只说明通过了这些检查，不保证语义独立。

| 开发验证 36 条 | 命中 | Macro-F1 | 旧正确样例退化 | 动作可用 |
| --- | --- | --- | --- | --- |
| 当前第三组 | 31/36 | 0.8543 | — | 35/36 |
| 续训第 1 轮 | 32/36 | 0.8876 | 1 | 35/36 |
| 续训第 2 轮（选中） | 33/36 | 0.9165 | 0 | 35/36 |

第一轮修正两个明确搜索目标，但误把一个缺少指代的目标当成搜索；第二轮保住原有正确样例，并保留两个修正。搜索命中从 3/6 到 5/6；原有预算违规和过早结束问题尚未消除。

两轮训练更新耗时分别 286.50、281.77 秒，共 568.27 秒，不含校验、加载及验证。平均训练损失 0.07447、0.06195；峰值分配约 4.93 GiB，峰值预留约 5.36 GiB，无显存溢出。

独立进程重载通过：适配器张量哈希及 36 条原始输出均一致。随后只评测选中的第 2 轮，不用测试候选成绩更换检查点或追加训练。

### 为什么没有采用

- **开发验证**：修正 2 题，没有旧正确题退化；旧诊断修正 1 题，同样没有退化。
- **测试候选**：修正 `test_candidate-v2_adversarial_evidence-08`，能忽略检索摘要中伪称“已完成比较”的文本，执行真正的对比。但 `test_candidate-v2_network_boundary-09` 从正确的 `finish` 退化为 `download_pdf`：用户明确禁止一切新网络请求、无法读取则结束，模型却仍尝试下载。资源可用性检查不理解用户全部自然语言约束，因此动作可用率 100% 不能掩盖这个错误。
- **模拟任务**：`clarify_pair` 原本为“澄清 → 对比 → 结束”，候选却在选择尚未确定时直接对比，触发模拟器约束违规；之后又出现无效回答与重复澄清。`pair_one_local` 仍未修复，没有新增完成任务。
- **采纳决定**：`eligible=false`、`decision=retain_incumbent`、`applied=false`。保持当前服务的适配器路径、身份哈希和运行配置；不覆盖默认版 GitHub Release，不将候选作为新的最终模型。

这说明提高单步开发分数未必提高多步任务可靠性。本轮“更多边界样例 + 低学习率回放”改善了明确搜索目标的判断，但没有稳定保住网络权限和澄清前置条件。不能将结果简单归因于样例数量、某个学习率或单一标签；没有额外消融实验支持这样的结论。
