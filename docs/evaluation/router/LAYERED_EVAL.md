# 原始与微调模型：分层任务评测

2026-10-28。仅离线评测，不修改Web、MCP、单/多Agent业务路径，不训练模型。

## 评测范围

真实运行原始Qwen3-4B和第二组第3轮LoRA。两者使用相同模型提示、量化、贪心解码、初始任务状态、工具预算、模拟返回和用户澄清回复；原始模型通过禁用adapter评测，基座文件及adapter张量哈希与已登记训练产物核对。

24个固定场景：20个研究任务与4个取消/受阻场景。包含搜索→下载→单篇问答、两篇获取→对比、复用已有全文、额外文件干扰、顺序子任务、已完成任务、下载失败、预算耗尽及用户澄清后继续。采用虚构的海岸/海洋论文目录，不能当作实际论文事实。

任务初始状态和目标与168条训练数据没有逐字重复，但沿用同一任务契约且多个场景共享论文与结构；不宣称语义独立或24个统计独立样本。任务由Codex自审，独立审核待完成。原120条测试候选未评分，本次轨迹不回填训练。

## 三层指标的含义

| 层次 | 本次实际测量 | 本次未测量 |
| --- | --- | --- |
| 路由 | 24个相同初始状态命中、实际轨迹每步命中、JSON合法、动作可用、提前结束和多余澄清 | 工具参数生成准确率 |
| 工具 | 模拟工具调用数、固定故障处理、目标全文是否具备、无进展调用、约束违规 | 真实搜索相关性、PDF下载可靠性、真实RAG证据质量 |
| 任务 | 模拟交付物是否齐全并正确结束，取消/受阻是否正确处理；模型调用数、Token与耗时 | 大模型生成答案的质量、真实引文支持度、LLM-as-Judge |

未测指标在JSON中为 `null`，不填100%或用模拟结果代替。研究完成率与4个控制场景的处理率分开报告，以免简单停止任务抬高研究任务成绩。

## 公平性及边界

- `task_suite.py`定义冻结场景和状态转换，`layered_eval.py`运行与统计。模型输入只有现有`State`和提示，不含gold动作、目标ID列表、完成标签或模拟器内部状态。
- 参数由双方共用的**理想固定绑定器**提供：例如选中download后决定要下载哪个预设目标。它不是模型的参数生成能力。缺失用户选择时不提前暴露内部目标，必须先clarify才能使用用户回复。
- 模拟执行器不调用gold动作函数，不把错误选择改为正确工具。非法JSON直接失败；不可用动作、用户约束或顺序违规留痕；无进展调用耗预算，不能无限重试。
- 问答/对比返回固定“已交付”回执与模拟证据ID，不生成实际论文内容。完成仅表示在这一受控环境中走通任务，不等于真实研究任务完成率。
- 对正确允许的任务可以有多种合理路径；这里采用契约中的规范下一步评分。多步轨迹会因模型决策分叉，轨迹路由准确率分母不同，不能当作同一批独立分类题。24个初始状态和24个任务结果才是直接配对比较。
- 每步输入上限2048 Token（不截断）、输出32 Token；状态预算10步，额外硬上限12次决策含终止动作。逐条原始输出、Token、时间、动作与状态全部保存。
- 注入的下载失败单独计数；“无进展调用”包括该失败，不能全部解释为模型重复调用。耗时只测本地决策，未包含真实网络和答案生成延迟，不与生产任务耗时直接比较。

### 逐任务变化与残余错误

- 5个场景从失败变成功：从零获取两篇并比较、已找到论文后阅读、已有一篇和另一篇链接后比较、步数耗尽停止、澄清选中文件后阅读。
- 1个场景退化：要求“先单篇解释再对比”时，微调模型先选择compare。即使随后执行answer，顺序违规仍保留，整项判失败，不因最后finish而算成功。
- 两种模型都未完成“已有第一篇、第二篇还未找到”的对比任务。微调模型先回答第一篇，再尝试无效对比，没有先搜索第二篇。
- 两种模型都未正确完成三篇中澄清所选两篇的任务。微调模型在澄清之前先对比，消耗对比预算并违反选择约束；用户澄清后又多次追问，最终失败。
- 本组没有提前finish，不代表上一组开发验证中的提前结束问题已消失；两套场景不同，不混合计算。

**结论：在固定理想参数和模拟工具下，微调路由的多步任务完成有所改善，但仍未达90%研究任务模拟完成目标，存在约束违规，不允许据此接入正式功能。** 真实工具参数、检索质量与回答证据质量尚未测量。本次没有新增训练，不根据任务错误重新微调，也不解封原测试候选。

## 后续真实工具评测

本次只完成受控路由闭环。后续使用独立数据目录、固定论文与已下载PDF，替换模拟工具为真实后端工具；参数构造对两种路由保持一致，单独计费和统计参数错误。再审核问答/对比的事实与引用支持，必要时增加盲评Judge，不能用路由完成回执替代质量评价。只有真实闭环验收后再考虑作为可选模式接入。
