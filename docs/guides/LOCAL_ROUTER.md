# 单 Agent 本地微调路由

研究任务助手新增可选的「本地微调小模型（实验）」路由，默认仍为云端大模型。多 Agent、检索计划、摘要、问答和对比的生成模型配置保持不变。

| 模式 | 选择下一步操作 | 生成工具参数、澄清问题和研究内容 |
| --- | --- | --- |
| 云端大模型（默认） | 云端模型 | 云端模型 |
| 本地微调小模型（实验） | 最终版Qwen3-4B QLoRA适配器 | 云端模型 |

本地模式仍需配置`LLM_BASE_URL`、`LLM_API_KEY`和`LLM_MODEL`，并不完全离线，也不保证总云端调用减少。当前已按用户要求作为实验选项接入，原离线指标和失败记录保留，不表示通过了原计划中的全部上线门槛。

## 启动

现有Windows本地后端和前端照常启动。另开一个WSL Ubuntu终端，运行：

```bash
cd /mnt/d/github/Project/PaperScout
~/.venvs/paperscout-router/bin/python -m training.router.serve
```

这是已有的独立训练环境，不需要把PyTorch安装进Windows后端环境。服务先校验并加载基座和适配器；首次启动需等待。看到`"ready": true`后，服务地址为`http://127.0.0.1:8010`。默认只监听本机回环地址，不应向公网开放。

默认使用本地文件：

```text
outputs/router/models/Qwen3-4B-Instruct-2507/
outputs/router/formal-20261028-03/epoch-3/adapter/
```

若已删除模型，先按[适配器恢复说明](ROUTER_RELEASE.md)重新准备固定版本基座及适配器，再显式指定位置：

```bash
~/.venvs/paperscout-router/bin/python -m training.router.serve \
  --model-path /path/to/base-model \
  --adapter-path /path/to/paperscout-router-v1.0.0/adapter
```

服务不依赖原训练日志，固定文件哈希在`training/router/runtime_profile.json`中；不自动下载、不自动切换基座。服务关闭后释放模型显存，需要时重新启动。

Windows后端默认连接上述8010端口，通常不需要修改`.env`。若改用其他端口，可设置并重启后端：

```dotenv
LOCAL_ROUTER_URL=http://127.0.0.1:8010
```

本次验证的是「Windows本地后端 + WSL2推理服务」。Docker容器中的`127.0.0.1`指向容器自身，不能直接套用此地址；需要额外配置宿主机连通地址，Docker跨WSL连接尚未验收。

## 网页使用

1. 研究任务助手选择「单 Agent」。
2. 「工具路由」选择「本地微调小模型（实验）」。
3. 输入目标（本地模式最多1500字），可选已有PDF，启动任务。
4. 执行记录显示小模型选中的操作；历史记录保留路由模式和模型版本。
5. 若任务需要澄清，在问题下填写「补充信息」，点击「补充并继续」。可以刷新后从历史中继续，也可以取消。切换回云端模式需要发起新任务，运行中不切换。

预算、已尝试动作、候选、下载失败记录和结果随任务保存，澄清后不清零。最多两次澄清，整体仍受10步、累计10分钟、工具次数与云端预算约束。并发只允许一个正在执行的研究任务。

## 执行与校验

- 小模型只返回route，后端检查资源及预算许可后，云端只能在已选工具的schema中生成参数；参数改选工具会被拦截。
- 候选paper_id和已导入reading_id分开使用。已尝试下载的候选不能重新下载，外部PDF ID不能跨任务调用。
- 小模型服务断开、繁忙、超时、版本不匹配或输出非法时明确停止，保留结果，不静默回退到云端路由。
- 完成判断与研究结论仍受工具实际产物约束；finish也可能代表受阻结束。记录是完成状态说明，不是论文事实证据。
- 状态不进行隐式截断，超过2048个输入Token会拒绝；大型或长目标任务请改用云端模式。
- 模型仍可能选错语义上不合适但资源合法的操作，因此这是可选实验模式。

## 已验证范围

- 后端测试覆盖模式隔离、固定工具参数、非法路由、服务错误、取消、澄清后预算/历史恢复及提示词一致性。
- 浏览器测试覆盖默认云端、本地切换、澄清提交、历史查看和多Agent兼容。
- 初次联调使用真实本地最终模型通过HTTP驱动后端，完成`compare → finish`；参数和证据内容采用模拟数据。
- 2026-10-28 用户完成本地 v1.0.0 的网页真实任务：`search → download_pdf → answer → finish`，搜索命中真实 arXiv 缓存，实际下载 TinyAgent PDF，并由云端生成参数与证据回答。耗时20.74秒，本地路由4次、生成调用5次、Embedding调用9次；6处引用均匹配对应PDF页原文。
- 此为单例验收，回答未展开全部planner执行细节，不代表稳定成功率或所有离线门槛通过。完整条件见[真实任务记录](../evaluation/AGENT_EVALUATION_RESULTS.md)。多篇真实对比、澄清恢复及Docker跨WSL连通仍未在本轮验证。

建议首先选择两篇已上传PDF，要求「比较这两篇论文的方法」，检查执行记录、对比结果与引用。再测试从搜索开始的任务；如果非法路由被拦截，保留失败记录，不算作成功。
