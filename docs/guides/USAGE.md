## 论文检索与排序

1. 在检索词框输入 `small language models`，选择来源，开始检索。
2. 查看结果标题、来源摘要、原文链接和全文状态依据。
3. 修改年份或关键词，再次检索。
4. 从左侧最近检索读取历史快照。
5. 配置模型后，输入中文想法，生成计划；修改确认后再检索。

最多填写三行关键词，每行独立查询，每组每来源最多获取 100 篇；同来源的多组结果按排名交替合并、去重后保留前 100 篇。每个来源候选总量由后端固定为 100，不随关键词行数增加，也不提供用户配置；返回数量独立设置，默认 10、最多 100。候选先过滤、合并去重并排序，再截取前 N 篇；不足 N 篇时返回实际结果。arXiv 使用关键词 AND 查询，过窄时请减少关键词。日期筛选应用于来源返回的论文年份；arXiv 请求按提交日期筛选。

## 排序方式

来源支持相关性排序时，优先请求相关性顺序；来源没有该能力时，保留其默认顺序。每个来源对各行查询分别获取结果，交替合并去重后保留前 100 篇作为候选，不将用户选择的时间或引用量排序传给来源。

当前 arXiv 显式传入 `sortBy=relevance`，Semantic Scholar 使用 `/paper/search` 相关性搜索接口，无需另外传排序参数。今后接入不支持相关性排序的来源时，可以用默认顺序参与 RRF，但需要注明排序依据；RRF 只融合排名，不会将时间等默认排名转换成语义相关性。请求失败仍报告来源错误，不以移除排序参数作为通用重试方式。

| 方式 | 规则 |
| --- | --- |
| 相关性优先 | 单来源单查询保留来源顺序；多来源按 RRF 分数 `sum(1 / (60 + rank))` 降序排列 |
| 最新发表 / 最早发表 | 在本次候选内按日期降序 / 升序排列 |
| 引用量最高 | 在本次候选内按 Semantic Scholar 引用次数降序排列，未知值在已知值（包括 0）之后 |

单行查询保留来源排名；多行查询按各组第 1 篇、第 2 篇依次交替合并去重，避免第一行占满候选。部分查询失败时保留成功结果并提示；每组独立缓存。同一篇论文在同一来源只贡献一次 RRF 分数；重复记录合并时保留各来源排名。RRF 同分保留首次出现的顺序；日期、引用量同分则按相关性顺序排列。

arXiv 日期为首次提交日期，Semantic Scholar 日期为其记录的 publicationDate；同一论文合并时保留先遇到的有效日期。只有年份的论文按年份分组，排在同年精确日期之后；年份和日期都未知时排在最后。不会编造月日。

arXiv 不提供引用次数，只有同时匹配到 Semantic Scholar 候选时才能合并其引用数据，本版不额外批量补查。界面提示缺失比例；若全部未知，引用排序退化为相关性顺序。引用次数是来源元数据及缓存时的快照，不是实时统计。

时间和引用量排序只覆盖当前候选集，不代表全库排名。固定每来源 100 篇是检索范围与成本的取舍，不代表后续排名论文必然不相关，也不能保证找到特定经典论文。切换排序或返回条数后，点击“开始探索”应用；相同候选请求可复用缓存。

接口参数示例：`{"plan":{"queries":["transformer"]},"sources":["arxiv","semantic_scholar"],"limit":10,"sort":"relevance"}`。响应包含 `candidate_count`、`ranking_note`、`warnings`，论文包含日期、引用次数、来源排名及融合分数。

缓存保存原始候选，排序方式和返回条数变化后重新本地排序；候选数量与元数据版本进入缓存键。旧历史记录仍按原快照展示，不追溯重排。

## 全文状态含义

- 公开预印本：来源提供 arXiv 版本 PDF 链接。
- 公开全文链接：Semantic Scholar 元数据提供公开 PDF 地址，不保证它是出版最终版。
- 已获取摘要：已有摘要但未取得公开全文链接。
- 全文状态未知：现有元数据不足。

链接来自来源元数据；点击“获取公开 PDF”后才实际下载并验证。链接可能失效。没有链接不代表付费，网络失败也不代表付费。界面没有凭空判定“明确受限”的逻辑。

检索成功响应缓存 24 小时，包括真实空结果；失败不会缓存。检索记录和缓存保存在 `backend/data/paperscout.db`，历史接口返回最近 50 条。记录是查询当时的快照，不保证当前可访问性。

## PDF 全文摘要

上传 PDF 后，配置模型时会自动综合全文生成一份摘要，覆盖研究问题、方法、主要结果与局限。未配置模型时先保存文件，配置并重启后端后点击“生成全文摘要”。页面不再展示全文、章节导航或逐页/逐章节摘要。检索结果仍支持获取公开 PDF 后生成全文摘要；“概括来源摘要”始终明确标记未读取全文。

提取文本不超过 48000 字符时直接整体总结（仍受模型上下文容量约束）；更长论文在后台按文本长度提取信息，再综合所有中间结果生成一份全文摘要，不展示分段结果，也不只截取开头。任一环节失败都不会保存部分结果冒充完整摘要。全文摘要与代表性原句证据一起保存。模型选择原文片段编号，程序据此取回原句与页码，再与提取文本核验；未知编号会被拒绝。已有摘要在重新生成失败时保持不变。旧版章节总结不迁移为全文摘要；可选择历史论文重新生成。

上传解析在本地完成；配置模型时，上传后自动将提取文本发送给该云端模型，长论文可能调用多次并产生相应费用。可取消生成。下载/解析限时约 50/40 秒，全文摘要最长等待 30 分钟；模型单次调用超时为 120 秒；输出截断后不自动重试。

文件限制：20 MB、100 页、60 万提取字符。不支持加密 PDF 或纯扫描件 OCR。双栏、公式、表格和图片信息可能提取不完整；摘要以成功提取的文本为依据，不保证覆盖未提取的视觉内容。引句存在性核验不等于模型结论一定正确。

最近摘要可恢复文件记录及全文摘要；原文件仍保存在被 Git 忽略的 `backend/data/pdfs/`，记录存于 SQLite。未实现多用户隔离，不应直接公开部署。

公开下载仅使用检索结果中的全文链接，旧 HTTP 地址尝试升级 HTTPS，逐次校验重定向和公网地址，不绕过登录或付费墙。Fake-IP 代理地址可能被拒绝，此时可手动上传合法获取的 PDF。

主要接口：`POST /api/readings/upload?filename=...`（原始 PDF 请求体）、`POST /api/readings/import`、`GET /api/readings`、`GET /api/readings/{id}`、`POST /api/readings/{id}/summary`。旧的章节总结接口已移除。内部仍保留页码信息用于证据校验。

更新依赖：

```powershell
.\.venv\Scripts\python -m pip install -r backend\requirements-lock.txt
```

## 引用生成

每条检索结果提供“生成引用”：展开后选择 GB/T 7714—2015 在线资源参考格式或 BibTeX，可编辑引用日期和条目后复制。复制被浏览器拒绝时会选中文本，支持手动复制；不调用模型或额外联网。不会自动添加论文中的参考文献编号。

引用只使用已获取元数据。缺少作者或年份时显示提示；不编造期刊、卷期、页码。当前文本格式属于在线资源参考条目，作者保留来源原名，不保证符合所有期刊/学校的最终格式要求。arXiv 条目指向预印本版本，不混入可能属于正式发表版本的 DOI；BibTeX 使用通用 misc 类型并保留已有作者、年份、链接及 arXiv 编号。正式期刊版引用仍需补齐出版信息后核对。

格式参考：[GB/T 7714—2015 原文（清华大学图书馆）](https://lib.tsinghua.edu.cn/wj/GBT7714-2015.pdf)、[CTAN BibTeX 引用说明](https://ctan.org/help/references)。这里明确提供 2015 版参考格式，并非声明采用最新版本；请遵循投稿或学校要求。


摘要降耗：已识别的阿里云 DeepSeek V4 / V3.2、Qwen3 服务请求关闭深度思考；DeepSeek 官方兼容模型使用其对应开关，未知服务不传厂商专属参数。请求 JSON 紧凑编码，减少格式开销。后台日志可记录服务返回的输入、输出、推理子项和总 Token；不展示到页面，不把推理子项再次加到总量中，未提供的字段记为未知。原有显式 LLM_SUMMARY_MAX_TOKENS 配置继续生效。

## 单篇论文问答

在“最近摘要”选择一份已上传 PDF，或上传/获取新 PDF 后，在摘要下方“问这篇论文”输入问题即可。问答不依赖摘要是否生成成功；每个问题独立检索，不自动携带以前的对话，建议使用完整问题而非“它呢”等指代。来源摘要记录不支持全文问答。

- 回答按要点附原文片段、章节和 PDF 物理页码；证据只来自当前论文，不跨文献。默认从整篇论文检索相关片段，无需选择章节。
- 找不到片段或模型认为依据不足时明确说明。检索缺失不等于原论文没有该内容；编号和原文可核验不等于推论一定正确。
- 默认最多检索 6 个、索引片段每个最多 1000 字符。排序后在原始片段内向前、向后各最多补 300 字符，尽量补齐句子，提供给模型和引用展示的证据每条最多 1600 字符。超长句或跨页句不能保证完整。每次最多调用一次回答模型，输出上限不超过 2048 tokens；不自动重试、不重新发送全文，不会自动生成新摘要。
- 支持取消；问答记录按论文保存在本机，最近 50 条可恢复。索引与问答数据沿用被忽略的 SQLite 数据库。

### 检索配置

未配置 Embedding 时使用本地关键词检索（BM25 评分，包含少量常见问题的中英文术语映射）。这是可直接试用的基础模式，不等同于跨语言语义检索；查询英文论文时可使用英文术语。它只需现有 `LLM_*` 模型配置。

使用语义检索时，在 `.env` 独立填写以下变量并重启后端：

```dotenv
EMBEDDING_BASE_URL=支持embeddings接口的服务根地址
EMBEDDING_API_KEY=该服务的密钥
EMBEDDING_MODEL=该服务支持的多语言向量模型名称
```

不自动复用生成模型的配置。三个变量应全部填写或全部留空；配置不完整会提示错误。服务应支持 `POST /embeddings`，返回带 `index` 的浮点向量，示例根地址以 `/v1` 或服务指定的兼容路径结尾。请使用多语言模型来支持中文问题检索英文论文。

首次语义提问会把整篇论文的片段分批发送给 Embedding 服务，生成向量后缓存；后续同一内容、服务和模型只需计算问题向量。向量归一化后使用 FAISS IndexFlatIP 检索，再与关键词排名融合。更换模型或文本会使用新缓存；服务失败不会静默回退到关键词模式。正文索引采用 SQLite 中的 JSON 向量持久化，FAISS 索引在查询时从缓存重建，不加载外来 pickle。

问答模型只接收问题及检索到的片段；Embedding 服务与回答服务可能不同，首次索引会产生独立向量调用费用。没有新增 Token 用量页面。

接口：`GET /api/readings/{id}/questions` 获取当前论文记录；`POST /api/readings/{id}/questions` 接收 `{"question":"这篇论文的局限是什么？"}`。问题最长 1500 字符，单次问答含首次索引的服务端总超时为 240 秒。索引失败时完整批次未全部完成则不写入缓存。

## 多篇论文对比

在摘要面板下方的“多篇论文对比”中选择 2～5 篇已上传的 PDF，再选择研究目标、方法、实验设置、实验结果或局限，点击“生成对比”。仅有来源摘要的记录不可选，不要求已生成全文摘要。结果按维度排列为表格，移动端可在表格内横向滚动；展开依据可查看对应论文的原文片段和物理页码。

研究目标优先直接选取摘要/引言证据，能够取到时不建立全文向量索引；其他维度或未识别摘要/引言时，逐篇、逐维度复用全文检索。每组最多取 2 个片段（补齐句子后每片段最多 1600 字符），一次回答模型调用整合为表格，输出上限 4096 tokens，受已有摘要输出预算的更低配置约束。不再次生成摘要，不将所有全文直接发送给回答模型；Embedding 索引复用问答的缓存，首次建索引仍会产生独立费用。最多 5 篇、5 个维度的输入可达约 80000 字符加提示词，费用随选择数量增加。

证据编号必须属于对应论文及维度，禁止引用另一篇论文的证据；缺失、重复单元格或错误证据会拒绝整个结果。未检索到信息明确提示，不代表原论文没有该内容。不同实验条件下的指标不能直接比较优劣，模型提示要求保留指标与条件，但证据校验不等于语义正确性保证。

成功结果保存到本地 SQLite，可通过“对比历史”恢复最近 20 次结果。失败或取消保留已有结果，不保存部分表格。服务端总超时 600 秒，不自动重试。

接口：`GET /api/comparisons` 获取历史；`POST /api/comparisons` 接收 `{"reading_ids":["论文ID1","论文ID2"],"dimensions":["goal","method","limitations"]}`。维度可选 `goal`、`method`、`experiments`、`results`、`limitations`。沿用现有 `LLM_*`、可选 `EMBEDDING_*` 配置，无新增配置项。

更新依赖并重启后端：

```powershell
.\.venv\Scripts\python -m pip install -r backend\requirements-lock.txt
```

检索实现参考：[FAISS 官方文档](https://faiss.ai/)、[阿里云 Embedding 模型说明](https://help.aliyun.com/en/model-studio/embedding-rerank-model/)。

## 单 Agent 研究任务

更新依赖后重启后端：`.\.venv\Scripts\python -m pip install -r backend\requirements-lock.txt`。页面的“研究任务助手”支持输入目标，例如“帮我找小模型调用工具的论文，选三篇并比较它们的方法”。可选中最多 5 篇已上传的 PDF 作为本任务资料，绕过公开下载不可用的情况。沿用 `LLM_*` 与可选 `EMBEDDING_*`，无需新增密钥。

LangGraph 使用 `decide → execute → decide` 的条件循环。模型每步返回一个经过 Pydantic 校验的结构化工具操作（JSON 协议，不依赖服务商原生 function calling），工具仅允许：

- `search`：每次只使用第一组核心检索词，保留年份条件，优先 arXiv；成功但空结果时去掉常见英文虚词，至少保留两个词并最多重试一次；网络错误不触发此重试。找到标题匹配且有公开全文链接的论文，或至少 5 篇候选带公开全文链接，且来源成功时跳过 Semantic Scholar，否则用原查询词补充 Semantic Scholar。两来源各最多 100 篇，合并去重并按 RRF 返回前 10 篇，继续复用来源缓存。最多两次搜索操作，第二次可改写关键词；来源选择及回退原因写入执行记录。这里的公开链接尚未验证下载，5 篇是候选数量阈值，不保证相关性或下载成功。顶部手动搜索仍按用户勾选的来源执行。
- `download_pdf`：仅根据本任务搜索候选的 paper_id 下载公开 PDF，复用公网地址校验、下载与解析；不接受模型生成的任意 URL。已有 PDF 已解析，直接使用 reading_id 调用 answer/compare，无需先下载。旧模型输出的 read 仅保留内部兼容解析，不再向模型展示。
- `answer`：对本任务已有 PDF 提问，复用检索和原文证据校验。
- `compare`：对本任务 2～5 篇 PDF 生成按所选维度组织的对比表。
- `finish`：结束任务。只报告任务状态，研究结论由已校验的问答或对比结果展示。

模型根据论文标题、截短来源摘要、当前可用 PDF、最近工具结果及剩余额度决定下一步，不将全部 PDF 反复塞入决策上下文。不自动逐篇生成全文摘要；用户需要归纳某篇内容时可由证据问答工具处理。工具错误会反馈给 Agent，它可以选择其他候选或结束；失败也消耗额度，重复操作会被阻止，所有重试均受限。

可选操作 schema 根据任务状态过滤：没有未尝试的公开 PDF 候选时不提供下载，没有已有 PDF 时不提供问答，不足两篇时不提供对比，额度耗尽的工具不再展示。运行时仍校验 ID 和调用预算。若把已有 reading_id 传给下载工具，会返回纠正提示，不下载、不将文档标记为不可读；连续两次此类误用会停止。

后台限制：最多 10 次决策、2 次搜索、5 次公开全文获取、1 次对比、2 次单篇问答，单任务总时间 600 秒；所有决策和回答合计最多 12 次生成调用、最多 80 次 Embedding 请求，累计模型请求输入最多 300000 字符。决策输出最多 2048 tokens，对比最多 4096、问答最多 2048，仍受显式配置的更低额度约束。这是调用次数和字符量上限，不是精确 Token 或金额预算；服务返回的实际 usage 继续记录在后端日志，没有新增费用页面。首次索引长论文可能达到输入上限，此时会停止任务并保留已产生的结果。

任务状态、执行事件、搜索记录、已获取 PDF 和结果持久化到 SQLite；刷新浏览器可以继续观察后台任务，关闭页面不自动取消，需点击“取消研究任务”。取消与超时停止后续操作，不保证服务商撤销已接收请求的计费。任务完成后保留最近 20 条可查看历史；服务异常重启后将运行中任务标记为中断，不会自动再次调用付费模型，用户可选已有 PDF 重新发起。当前面向本地单用户、单后端进程，一次只运行一个研究任务，请勿使用多 worker 启动方式。未实现跨进程任务队列或从中断图节点自动恢复。

接口：`POST /api/agent/runs` 接收 `{"goal":"研究目标","reading_ids":[]}` 并立即返回 202；`GET /api/agent/runs` 查看历史；`GET /api/agent/runs/{id}` 查询进度；`POST /api/agent/runs/{id}/cancel` 取消。运行结果可能为 `completed`（执行结束，需检查实际结果）、`partial`、`limited`、`failed`、`cancelled` 或 `interrupted`，不将缺失全文标作已读，不编造来源。

LangGraph 执行关闭 LangSmith 外部跟踪上传，仅使用本地任务记录。图执行依据：[LangGraph 官方 Graph API](https://reference.langchain.com/python/langgraph/graph)。当前自动化测试使用模拟模型与网络响应，实际执行 LangGraph 图；真实来源网络、模型决策质量及 Embedding 联调需另行验收。

## 可选多 Agent 模式

“研究任务助手”的执行模式默认是 **单 Agent**，原有流程保持可用；选择 **多 Agent** 可启用协调、检索和分析三角色。使用同一套 `LLM_*`、可选 `EMBEDDING_*` 配置，不需要新密钥或依赖。

LangGraph 路径为 `协调 → 检索或分析 → 工具执行 → 协调`。协调者决定下一项任务或结束；检索角色只能搜索、获取候选 PDF 或报告阻碍；分析角色只能调用证据问答、对比或报告阻碍。不同角色有独立提示词与 Pydantic 操作范围校验，共享候选、论文 ID、失败记录和简短已校验结果。已有 PDF 足够时可以直接委派分析，无需再搜索。最终结论仍来自原问答/对比工具，不使用角色自行撰写的无引用结论。

所有角色串行执行，角色决策和工具模型请求共用原有 12 次生成、80 次 Embedding、300000 输入字符、10 分钟限制，不为每个角色新增预算。多 Agent 最多 18 次角色决策，单 Agent 仍最多 10 次；实际可能先达到模型请求上限。搜索 2、下载 5、对比 1、问答 2 的上限保持不变。连续两次无操作报告或连续两次重复/超额工具请求会提前停止。角色分工可能增加调用与耗时，不保证优于单 Agent。

任务记录包含 `mode`（`single` / `multi`）和执行事件的 `role`。历史无 mode 时按单 Agent 展示；默认不打开历史结果。运行中不可更改该任务模式，两种模式仍共用“一次一个任务”的限制。取消、服务重启标记中断和已有结果保留机制共用；没有新增自动恢复或多 Agent 并行执行。

接口仍为 `POST /api/agent/runs`，新增可选字段：

```json
{"goal":"比较这两篇论文的方法与局限","reading_ids":["论文库ID1","论文库ID2"],"mode":"multi"}
```

省略 mode 默认 single。自动化测试使用模拟外部服务、实际运行两种 LangGraph 图；已有 PDF 的四次真实任务对照已完成，结果及工具语义修复后的复测记录见 [Agent 对照记录](../evaluation/AGENT_EVALUATION_RESULTS.md)；多次稳定性与同质量成本对照尚未完成。手动测试步骤见 [启动与演示说明](DEMO.md)。

公开 PDF 下载遇超时会在下载层自动重试一次，无需额外模型调用；单次尝试最多 25 秒，两次共用 50 秒总期限。取消、地址校验失败、HTTP 错误及无效 PDF 不触发该重试。真实单/多 Agent 验收记录见 [评测记录](../evaluation/AGENT_EVALUATION_RESULTS.md)。
